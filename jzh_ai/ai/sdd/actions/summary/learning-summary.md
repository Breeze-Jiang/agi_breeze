## 核心知识

### 1. 产品目标与最小数据流

**材料事实：** 插件面向英文网页阅读场景，一键提取文章核心内容，调用 AI 翻译，将结果以 Markdown 展示并复制。[E1]

最小数据流是：

```text
当前网页内容
→ 正文提取
→ 发送给所选 AI 模型
→ 接收翻译结果
→ 转换或渲染 Markdown
→ 用户复制
```

这个链路比“做一个翻译插件”更可执行，因为它已经暴露了正文提取、模型调用、格式处理和交互四个模块。

### 2. 为什么先定义 MVP

笔记强调先清晰定义“做什么”，再调研和验证需求，并明确返回格式与“不做什么”。[E2]

MVP（Minimum Viable Product，最小可行产品）的意义是先验证最关键价值，而不是一次做完所有设想。根据材料，最小范围可围绕“提取—翻译—Markdown 展示—复制”建立；模型切换、流式布局和公众号格式适配是否全部进入首版，仍需在正式需求中确认。

### 3. SDD 文档先行

笔记将 `proposal.md` 定位为需求文档，并要求在编码前调研难点、与 AI 或 Skill 讨论方案，只生成和验证文档。[E3]

合理的规划链路是：

| 产物 | 回答的问题 |
|---|---|
| `proposal.md` | 为谁解决什么问题，MVP 做什么、不做什么 |
| `design.md` | 正文提取、模型调用、Markdown 处理如何实现 |
| `task.md` | 模块怎样拆分、依赖是什么、如何验收 |

当前材料只提出这些方向，没有提供三份完整文件。

### 4. 技术难点与架构决策

材料指出技术选型直接影响项目成败，并提出三个重点：[E4]

- 网页主要内容如何提取；
- 通过 OpenAI 兼容接口切换 Qwen 等模型；
- 输出适合微信公众号使用的 Markdown。

材料还提到 `marked`，可合理推断其候选职责是解析或渲染 Markdown，但没有源码证明最终采用方式。[E5]

### 5. Git 与 AI 编程回退

笔记强调创建 Git 仓库，使 AI 生成过程可追溯、可回退，并按照“未暂存、已暂存未提交、已提交”区分处理。[E6]

更安全的心智模型是：

| 状态 | 先检查 | 常用处理 | 风险 |
|---|---|---|---|
| 未暂存 | `git diff` | `git restore <file>` | 丢弃工作区修改 |
| 已暂存未提交 | `git diff --staged` | `git restore --staged <file>`，再决定是否丢弃工作区修改 | 分两步更易确认 |
| 已提交 | `git log` / `git show` | 共享历史优先考虑 `git revert` | `git reset --hard` 会移动历史并丢弃修改 |

材料中的 `git restore .` 和 `git reset --hard` 都可能造成不可恢复的数据丢失，不能在未检查状态时直接使用。

### 6. AI 会话管理

材料要求开启会话管理以管理上下文，并指出聊天窗口关闭后信息可能丢失，而文档可记录和共享。[E7]

这体现了 SDD 的核心价值：把关键决策从临时会话迁移到版本化文档，使不同会话和不同 Agent 能读取同一事实基线。

## 重点语法与 API

### Git 命令 [材料中出现]

```bash
git restore .
git reset --hard
```

- `git restore .`：丢弃当前目录下未提交的工作区修改，具有破坏性。
- `git reset --hard`：移动当前分支并同步暂存区、工作区，可能丢失提交后修改。
- 更安全的使用方式是先执行 `git status`、`git diff`，并指定具体文件。

### `marked` [材料中出现]

材料只提到 npm 包 `marked`，没有展示调用 API。它可能用于 Markdown 解析或渲染，但具体接入方式未知。

### OpenAI 兼容接口 [材料中出现]

## 面试高频知识

### 为什么 AI 编程项目要先定义 MVP？[材料推导]

MVP 用最小范围验证核心价值，减少 AI 在需求边界不清时生成无关功能，也让任务和验收标准更容易明确。

### 为什么 SDD 需要写非目标？[材料推导]

只写“做什么”仍可能让 Agent 自行补全范围；明确“不做什么”可以限制架构和实现边界，降低需求蔓延。

### 为什么浏览器插件要重视网页正文提取？[材料中出现]

网页包含导航、广告、评论等噪声。如果输入内容不准确，后续翻译和 Markdown 输出也会受到影响，因此正文提取是上游关键环节。

### `git reset --hard` 和 `git revert` 如何选择？[外部补充]

`reset --hard` 会改写当前位置并丢弃工作区状态，适合确认未共享且允许重写的本地历史；`revert` 新建反向提交，更适合公共历史。

### 模型可配置的架构价值是什么？[材料推导]

把业务流程与具体模型供应商解耦，可以按需求切换兼容模型；但兼容范围、鉴权和响应差异仍需设计层验证。

## 复习卡片

> [!tip] 最小心智模型
> 先确认用户价值和非目标，再确定技术路线，最后把设计拆成可验收任务。

1. 插件的核心链路是什么？——提取正文、AI 翻译、Markdown 展示、一键复制。
2. MVP 是什么？——能验证核心价值的最小可行产品。
3. 为什么写“不做什么”？——限制需求和 Agent 的推断范围。
4. 网页正文提取为什么重要？——上游输入质量决定翻译质量。
5. 文档为什么优于临时会话？——可持久化、共享和版本控制。
6. Git 在 AI 编程中的作用？——保存可追溯节点，便于审查和回退。
7. `git restore .` 的风险？——会丢弃工作区修改。
8. `git reset --hard` 的风险？——可能移动历史并丢失未保存修改。
9. 当前是否已经完成架构设计？——没有，材料只有方向性笔记。
10. 当前项目是否运行验证？——没有。
