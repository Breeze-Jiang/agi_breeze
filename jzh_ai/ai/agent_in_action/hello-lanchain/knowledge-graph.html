Tool 的工作机制
定义两个部分： ① 异步处理函数（干活的逻辑）   ② 描述对象（name + description + schema）
调用流程： LLM判断需要Tool → 停止生成 → 返回 tool_calls{id, name, arguments} → 执行Tool函数 → 结果按id关联回会话 → LLM继续推理
并行执行： 多个Tool用 Promise.all([...]) 并行执行，提高性能
⏳
Promise 三种状态
pending → fulfilled
pending → rejected
状态不可逆
⏩
await (ES8)
异步变同步
代码更优雅
但会阻塞等待
🚀
Promise.all 并行
一起执行多个任务
等最慢的完成
结果顺序=入参顺序
⏱️
串行 vs 并行
串行：2000+500=2500ms
并行：max(2000,500)=2000ms
节省500ms!

💡 一句话总结

今天的核心就是理解 Agent = LLM + Memory + Tool + RAG + MCP + Skills —— 给大模型装上"记忆"让它记住你、"工具手"让它能干活、"知识库"让它懂内部文档、"实时联网"让它知天下事、"技能包"让它处理复杂任务。
开发框架用 LangChain（单智能体）+ LangGraph（多智能体）， 结合 NestJS 后端，打造能落地的 AI 全栈 Agent 产品。
性能优化关键：Tool 调用使用 Promise.all 并行执行，而非逐个串行 await。
