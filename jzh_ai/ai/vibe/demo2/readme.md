# Vibe Coding Harness 工具

## Vibe Coding 开发前的步骤和关键点

通过Vibe Coding ，项目推进特别快， 但是越往后， 代码越乱， 代码质量也越差。容易使整个项目崩盘

问题在哪
问题在于 vibe coding 不是说 ， 把这个活直接丢给ai

而是你还要构建一套工作流程，去驾驭ai 。 Harness Engineering

## Vibe Coding 标准工作流
### 开发前的9个步骤
规划就是一切
#### 三个阶段
- 第一个阶段 叫做定图纸
1.先别去写代码，先去到需求
就好像你去和朋友聊天一样，可以和claude 聊天，把痛点，（足够痛，没解决，有市场），把目标用户，把使用场景和你理想中的核心功能，全部讲给ai，不用追求严谨信息量，定完需求
2.定完需求后，把这个需求整理成一个PRD 文档，让开发者来验收。
让AI输出一份比较结构化的文档，它中间包括了功能列表，用户流程，页面清单，每个功能你都要补上一句，到底做到什么程度才算完成（边界）？
比如：登录成功，不是一句话， 要说清楚 登录失败提示是什么，登录成功以后跳转到哪里？（首页、登录前的页面？）
没有验收标准，ai会写的越来越发散
PRD.md （持久化，作为全局上下文）
3.提前订好视觉 ，和页面框架
找2-3个参考网站，或者让ai 去生成几种风格的方案。
我们决定，网页的布局，页面有哪些内容，整体使用简约风还是豪华风
为了后面，不让ai 一边去写代码（逻辑），一边去把UI 推倒重来
DESIGN.md 
- 第二阶段 打地基
4.明确项目的边界和非功能需求
本地跑？还是线上公开的？用户量是多少？ 有没有用户数据，支付，性能和成本有没有上限
安全、性能、可用性、成本 这四个非功能性需求不写清楚， 后面一定会返工
5.锁定技术栈，越可验证越好
适合的就是最好的，比如 react + ts + tailwindcss
6.让ai 出轻量架构草案。
目录架构怎么分层
核心模块有那些
数据模型长什么样
有哪些组件
- 第三阶段 立规矩
7.固化成文档
现在的agent和llm交互都会用一个文档，需要把PRD、设计、架构、当前状态
写成项目根目录下的几个文本， 固化下来
PRD.md(产品需求文档)
ARCH.md(系统架构文档)
Project.md(当前项目阶段)
Design.md(设计文档) 
...
这些文件都是ai的全局上下文， vibe codign 永久约束
8.定开发规范和建参考资料文件夹
- 代码规范
- 错误处理
api 接口
restful 规范
可以给一个样本参考
9.搞好git 和质量阀门
