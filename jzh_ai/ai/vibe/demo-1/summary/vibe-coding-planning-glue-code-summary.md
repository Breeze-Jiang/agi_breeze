## 核心观点

Vibe Coding 不是把需求一句话交给 AI 后等待结果，而是把 AI 当作协作开发者：先提供项目上下文和约束，再审核规划，最后让 AI 在明确边界内实现。

```text
模糊需求 → 规划 → 人工审核 → 小步实现 → 验证与迭代
```

## 第一步：规划优先

笔记以 React 19、Tailwind CSS、useState 的待办清单为例，要求 AI 第一阶段只输出规划，不写代码。规划应包括：

1. 技术栈；
2. 功能边界；
3. 模块拆分；
4. 数据结构和数据流；
5. 明确暂不做的功能。

案例中只做新增、删除、切换完成；不做本地持久化、筛选和拖拽。任务数据结构预先约定为：

```js
{ id, text, completed }
```

提前限定字段和边界可以减少 AI 自行新增功能、擅自改字段名等问题。

## 第二步：胶水编程

胶水编程的思路是：成熟能力交给成熟库，业务代码只做集成、适配和数据流转。

例如待办拖拽排序，不建议让 AI 从零手写鼠标坐标监听与排序逻辑；应先选择符合当前项目的成熟、维护活跃的拖拽方案，再让 AI 输出：

- 安装命令；
- 现有组件与库的衔接方式；
- 任务数组在排序后的更新逻辑。

重点不是“不写代码”，而是不重复造复杂、边界多且难维护的底层轮子。

## 第三步：用反馈改进协作规范

笔记提出通过记忆模块、提示词规范或评审机制，让 AI 根据生成结果持续调整。实际执行中可将稳定规则固化为项目文档，例如：

- 使用的技术栈和版本；
- 命名和目录规范；
- 每次变更范围；
- 是否允许安装新依赖；
- 必须执行哪些检查。

## 面试表达

> 我把 AI 当作协作开发者而不是一次性代码生成器。先让它理解技术栈并输出功能边界、模块划分和数据结构，审核后再分步骤实现。对于拖拽、鉴权等复杂能力，优先采用成熟方案，我负责组件适配、数据流转和验证。这样能降低生成代码的幻觉和维护成本。
