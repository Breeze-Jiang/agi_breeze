# AI workflow 工作流
coze 构建工作流
选择节点 （输入 输出）
适合将智能融入既定流程，需要稳定执行的流程中
FDE 工程 神器 workflow 适合为流程性工作提效，自动化
workflow 本质上是一套预定义的流程，可以把他想象成一套生产的流水线。每一步都有明确的输入和输出
每个节点的逻辑是固定好的，当条件满足，就会进入下一环节，
在技术上，它通常变成一个编排好的工作流引擎
一个由ai调用，条件判断，循环逻辑组成的一个图谱

langchain 是用于快速搭建工作流的开发框架，灵活构建各类智能任务链路

很多人会混淆


## Agent 智能体
和workflow 逻辑完全不一样，不走在一条预设的轨道上，而是站在一个开放的空间，自己去探索怎么去做（智能），从技术上 ，一个Agent 往往具备三个大的核心能力

1.感知环境
通过输入文本、图像、数据来感知环境。有哪些工具可以调用，当前情况如何，如何分步骤，如何规划，
2.规划路径
不是预先定义好的，而是动态去生成任务链
3.执行任务
去调用工具，完成子任务，并不断地去调整

## 举例
你让agent 去规划流程，它可能会先去搜一下机票和酒店价格。再去查天气和签证需求。然后结合偏好和预算，动态权衡方案。
整个地过程中，可能走的路径和你预期的完全不同，这是agent的关键区别
，有自主性和适应性
本质区别在于：workflow是确定性的执行路线，很清晰，很固定，效率很高，但是能到达既定的终点


所以，从产业角度，workflow 更适合流程化，重复性任务，比如审批流程， 数据清洗
agent 更适合动态的 一个角色场景

从技术栈的领域，workflow 更依赖与规则，图形化编排，（coze），流程引擎，agent 更依赖与大模型的推理能力和记忆能力，包括工具调用等，

未来我们的AI 工程中将会集合agent 和workflow 的双重能力
底层是workflow 去提供稳定性和可控性，上层是agent 提供灵活性和智能性

workflow是骨架，agent是workflow的大脑

workflow 缺点是没什么创造力， agent 有，但是不可控不可预测，所以一起结合，既高效又有智慧
