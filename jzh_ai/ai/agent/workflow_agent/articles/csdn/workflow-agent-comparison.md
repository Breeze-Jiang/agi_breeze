# Workflow 与 Agent 怎么选？从“AI 流水线”到“会规划的智能体”

做 AI 应用时，经常会听到两个词：Workflow 和 Agent。它们都能“让 AI 干活”，但解决的问题不同。

一句话先记住：

> Workflow 擅长按既定步骤稳定执行；Agent 擅长面对开放目标自主规划。真正的生产方案常常是两者结合。

## Workflow：把任务做成可控流水线

Workflow 是一套提前设计好的流程。节点的输入、输出、判断条件和下一步去向都比较明确。

```text
输入
  → 节点 A
  → 条件判断
  → 节点 B
  → 输出
```

一个典型场景是招聘简历筛选：

```text
PDF 简历
  → 解析文本
  → 提取技能、工作经历、教育背景
  → 与岗位要求匹配
  → 输出匹配结果
```

这类任务的流程基本固定，所以适合用 Workflow。它的优点是：

- 路径清晰，容易理解和排查；
- 输出过程可审计；
- 适合重复任务自动化；
- 关键操作更容易添加规则和权限控制。

审批、信息抽取、数据清洗、固定格式报告生成，都属于典型 Workflow 场景。

## Agent：面对目标自主规划

Agent 不要求把每一步预先写死。它接到目标后，会根据上下文决定下一步做什么。

一个 Agent 的核心能力可以概括为：

1. **感知**：理解用户输入、当前数据和可用工具。
2. **规划**：把大目标拆成子任务，并动态决定顺序。
3. **执行与调整**：调用工具，根据中间结果修改计划。

例如“规划一次旅行”，Agent 可能按这样的路径工作：

```text
理解预算和偏好
  → 查询机票、酒店
  → 查询天气和签证
  → 对比多个方案
  → 输出推荐行程
```

但它也可能先查签证，再查机酒。路径会随用户约束和查询结果变化，这正是 Agent 的自主性和适应性。

## 两者的本质区别

| 对比维度 | Workflow | Agent |
|---|---|---|
| 执行路径 | 预先定义 | 动态规划 |
| 擅长内容 | 稳定、重复、规则明确的任务 | 开放、复杂、变化多的任务 |
| 依赖能力 | 流程编排、节点、条件和规则 | 大模型推理、记忆、工具调用 |
| 主要优点 | 可控、高效、易审计 | 灵活、能处理不确定问题 |
| 主要问题 | 缺乏创造性，适应变化较弱 | 行为可能不可预测，需控制成本和风险 |

## 为什么不能只用 Agent

如果把涉及退款、审批、数据库写入等关键操作完全交给 Agent 自由决定，会有明显风险：

- 它可能选错工具或走错步骤；
- 推理路径不稳定，难以复现；
- 可能产生不必要的调用成本；
- 审计和权限控制更复杂。

因此，核心业务动作不应该只依赖自由规划。

## 更实用的架构：Agent 做大脑，Workflow 做骨架

生产环境中常见的组合方式是：

```text
用户请求
  → Agent：理解意图、规划、选择处理路径
  → Workflow：执行查询、校验、审批、写入等固定步骤
  → Agent：整合结果并回复用户
```

例如客服系统：

```text
用户：“我的订单可以提现吗？”
  → Agent 判断意图：订单与退款问题
  → Workflow 查询订单、校验退款资格、创建工单
  → Agent 用自然语言解释处理结果
```

这样分工有两个好处：

- Agent 保留自然语言理解和灵活路由能力；
- Workflow 把关键业务操作限制在可控、可追踪的流程内。

可以用一句形象的话概括：

> Workflow 是骨架，Agent 是大脑。

## 工程落地时的三个控制点

即便使用 Agent，也要加约束：

1. **工具白名单**：只允许调用明确批准的工具。
2. **最大执行步数**：避免无限循环或无意义调用。
3. **人工确认点**：退款、删除、转账等高风险操作必须二次确认。

这些措施的目标不是削弱 Agent，而是让它在正确边界内发挥能力。

## 总结

- 任务步骤固定、需要稳定交付：优先 Workflow。
- 任务目标开放、需要自主规划：考虑 Agent。
- 既要智能又要可靠：用 Agent 负责决策与路由，用 Workflow 执行标准化动作。

## 面试回答

> Workflow 是预定义的确定性任务编排，适合流程清晰、重复性高且强调可控性的业务。Agent 则利用大模型完成感知、规划、工具调用和动态调整，适合开放性任务。实际工程通常采用 Agent + Workflow：Agent 做意图理解和决策，Workflow 承担关键、标准化、可审计的执行流程，从而平衡灵活性与稳定性。
