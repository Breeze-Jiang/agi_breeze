## 一句话理解

- **Workflow（工作流）**：把任务拆成预先定义的节点，按固定规则流转，重点是稳定、可控和高效。
- **Agent（智能体）**：围绕目标动态感知、规划、调用工具和调整步骤，重点是自主性与适应性。

## Workflow：AI 的流水线

工作流是一套预定义流程：每个节点都有明确输入、输出和转移条件。满足条件就进入下一步，常见实现包括 AI 调用、条件判断、循环和流程编排。

以招聘简历处理为例：

```text
PDF 简历
  → 解析文本
  → 提取技能、经历、教育背景
  → 匹配岗位要求
  → 输出匹配结论
```

这种任务的步骤相对固定，适合用 Workflow 自动化。它常用于审批、数据清洗、信息提取等重复性工作。

## Agent：能自己决定路径的执行者

Agent 不严格沿着一条固定路径执行。它通常具备三类能力：

1. **感知**：理解用户输入、当前环境和可调用工具。
2. **规划**：根据目标动态拆分任务和安排步骤。
3. **执行与调整**：调用搜索、数据库、接口等工具，依据中间结果继续调整。

例如旅行规划任务，Agent 可能先查询机酒价格，也可能先查天气、签证，再结合预算和偏好重新规划。这条路径不一定能提前写死。

## 核心对比

| 维度 | Workflow | Agent |
|---|---|---|
| 路径 | 预先定义 | 动态生成 |
| 重点 | 稳定、可控、效率 | 灵活、自主、适应 |
| 技术侧重点 | 规则、节点、流程引擎、图形化编排 | 大模型推理、记忆、规划、工具调用 |
| 典型任务 | 审批、数据清洗、固定信息处理 | 研究、规划、复杂角色任务 |
| 风险 | 创造力和适应性较弱 | 行为不够可预测，成本和安全需要约束 |

## 为什么要结合

实际 AI 工程不应简单二选一。更实用的方式是：

```text
Agent 负责理解目标、规划和决策
        ↓
Workflow 负责执行标准化、可审计的子流程
```

可以把 Workflow 看成骨架，把 Agent 看成大脑：Workflow 为系统提供稳定性和可控性，Agent 提供灵活性和智能性。

例如客服运营系统：Agent 判断用户意图、决定是否需要升级处理；确定性的订单查询、退款校验、工单创建则交给 Workflow 执行。这样既避免让模型自由执行关键操作，也能处理多样化的用户问题。

## 面试表达

> Workflow 是预定义的确定性任务编排，适合稳定、重复、流程清晰的业务；Agent 则基于大模型进行动态规划、工具调用和结果调整，适合开放性、变化较多的任务。生产系统通常采用 Agent + Workflow：由 Agent 做决策和路由，由 Workflow 执行关键的标准化流程，以平衡智能性、稳定性与可控性。
