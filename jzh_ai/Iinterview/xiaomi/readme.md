## 闭包 closure 
- 为什么又闭包这个概念
词法作用域的规则和函数调用完毕他的执行上下文一定会被销毁这一规则冲突。
解决冲突的办法 将内部函数需要使用的变量（自由变量），放到闭包（背包）中，
持久化的放到堆内存里，（不会被垃圾回收），内部函数运行outer指向背包，拿到变量
闭包的缺点
- 会保持对其外部作用域的引用，可能导致内存无法被及时释放，内存泄漏
如果闭包持续存在，并且外部作用域的对象也被闭包引用，对象无法垃圾回收，可能导致再调用栈中的占用增加
- 每次创建闭包时，都会有额外的1上下文开销，尤其是在频繁创建闭包的情况下，可能会
理解作用域链（静态，函数声明时（非运行时）outer 指向外层函数） 时理解闭包的基础，闭包无处不在

- js代码的执行
  编译 准备执行上下文 作用域 变量环境，词法环境
  作用域链（变量查找的路径）

## 作用域链

调用栈、执行上下文、词法环境、变量环境（outer） 闭包变量（背包对象）堆内存中
每个执行上下文的变量环境中，都包含一个外部引用，用来指向外部的执行上下文。
这个外部引用称为outer。

内部函数运行时， 查找变量， js引擎 当前执行上下文 -> outer -> ---全局
变量的查找规则 路径 作用域链

## 词法作用域
词法作用域 就是 作用域是由代码中函数声明阶段的位置来决定的。多以词法作用域时静态的作用域。通过它能够预测代码再执行过程中如何查找变量标识符

js的作用域链是由词法作用域链来决定的
词法作用域是代码编译阶段决定的，和函数是怎么调用没有关系。

## 闭包

在js中，根据词法作用域的规则， 内部函数总是可以访问其外部函数中声明的变量，当通过调用一个外部函数返回一个内部函数后，即使该外部函数已经执行结束，但是内部函数引用外部函数的变量依然保存在堆内存中，我们把这些变量的集合称为闭包。

闭包 = 自由变量的集合， 在外部函数被销毁后，还能访问

### 闭包是怎么回收的？

如果该闭包会一直使用，那么它可以作为全局变量存在，不会被垃圾回收。
但是如果使用频率不高，而且内存占用又比较答，那就尽量让它成为一个局部变量


如果引用闭包的函数是一个全局变量，闭包会一直存在到页面关闭
如果这个闭包以后不再使用的话，就会造成内存泄漏

如果使用闭包的函数是一个局部变量，函数销毁后， js引擎执行后垃圾回收是， 判断后， 回收这块内存
