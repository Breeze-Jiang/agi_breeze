# agent 智能体
字面意义上，ai会自己干活
这么理解没问题，但是遮住了一个更重要的问题

agent和普通的ai对话 到底差别在哪里
- 对话结构
普通对话，你问他答，一问一答就结束
案例 帮我写一封邮件
问答机器 输出一次，没有后续
agent不一样 它有一个持续运转的结构
你给他一个任务 他会去拆任务，决定下一步，去调工具，看结果
这过程是一个循环吗，知道任务完成，或者它自己判断（超过循环次数，token上限，相同结果次数，未完成）

##　agent 工作方式，核心三个动作
- 第一个动作 思考 reason
- 第二个动作 执行 act
- 第三个动作 观察 observe

一轮的，观察后再回到思考，再行动，再观察，循环往复，这个循环就叫react loop
react （reasoning + act + observe）是一套标准的 agent执行流程/agent工作框架，不是langchain那种大型的开发库，是agent通用的循环工作标准


## demo
帮我写分析的竞品，然后去写一份报告。agent 会这么做。

- 第一轮它先去思考（reason）
  需要去搜索竞品的信息
  调用搜索工具（act），去咨询三家竞品的最新动态
  查完以后，把结果拿回来
  然后观察（observe）信息量挺大
  到这里第一轮结束了，接着：

  再回到思考，发现缺少财务数据（reason）
  可以去官网或查股市api（act）
  去抓取相应的数据
  观察
  第三轮，第四轮。。。
  最后一轮，把报告写完，交给我们

agent 最核心的动作，就是tool use
工具是agent的手和脚，没有工具，它只能在脑子里转，转完之后，只有文字
常见的工具；
- 搜索工具，能上网查实时信息
- 代码执行器，能运行代码，能看结果。
  anthropic 最牛逼的agent企业，代码是最标准，有完善工程化验收机制的，ai测试agent
  
- 文件读写I/O

- 浏览器的操控 browser 打开网页，点击提交，
  manus
- api调用
工具越多，agent能干的事情越多
很多agent产品，调用很多工具，工具覆盖范围。直接决定agent的能力边界，选择agent的核心
