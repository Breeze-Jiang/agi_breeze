  一、核心概念（来自 readme.md）

  执行上下文对象包含三部分：

  ┌────────────┬───────────────────────────────────────┐
  │  组成部分  │               存储内容                │
  ├────────────┼───────────────────────────────────────┤
  │ 变量环境   │ function、var 声明的变量和函数        │
  ├────────────┼───────────────────────────────────────┤
  │ 词法环境   │ let、const 声明的变量，支持块级作用域 │
  ├────────────┼───────────────────────────────────────┤
  │ 可执行代码 │ 从上到下顺序执行                      │
  └────────────┴───────────────────────────────────────┘

  调用栈（Call Stack）

  - V8 引擎用来管理函数调用关系的数据结构
  - 编译总发生在执行前一刻
  - 全局和函数体编译时会生成执行上下文对象，压入调用栈
  - 函数执行完毕后，其执行上下文弹出并销毁
  - 程序运行前，调用栈是空的

  编译阶段四步走：

  1. 创建执行上下文对象
  2. 找形参和变量声明 → 变量名作为 key，值设为 undefined（变量提升）
  3. 统一形参与实参（全局环境无此步骤）
  4. 找函数声明 → 函数名作为 key，值设为函数体（函数提升）

  let / const 的特点：

  - 存储在词法环境中（非变量环境）
  - 支持块级作用域
  - 不会变量提升，存在暂时性死区（TDZ）
  - 不能重复声明
  - 词法环境也使用栈结构管理不同作用域的变量
  - 查找变量时：先查词法环境 → 再查变量环境

  二、示例代码解读

  1.js — 变量提升与函数提升的原始形态

  showName('fl');       // ✅ 函数提升，可提前调用
  console.log(showName); // 打印函数体
  var myName = 'fl';
  function showName(name){ ... }
  说明：函数声明整体提升，所以调用在声明之前也能正常运行。

  2.js — V8 视角下的"编译后"代码

  // 编译后等价于：
  var myuname;           // 提升，值为 undefined
  function showName(name){ ... }  // 函数整体提升
  showName();            // ✅ 正常运行
  console.log(myuname);  // undefined
  myuname = 'fl';        // 赋值留在原地
  这是 V8 引擎编译后实际执行的逻辑视图。

  3.js — 函数声明 vs var 同名时的优先级

  console.log(func);  // 打印函数体，不是 undefined
  function func(){}
  var func = 123;
  函数声明的优先级高于 var 声明，所以 func 先被初始化为函数体，var 的重复声明被忽略。

  4.js — 函数内部编译过程（形参、var、函数声明三者博弈）

  var a = 1;
  function fn(a) {       // 形参 a 接收实参 3
    console.log(a);      // → 打印 function a(){}
    var a = 2;
    function a(){}       // 函数声明覆盖形参
    var b = a;
    console.log(a, b);   // → 2, 2
  }
  fn(3);
  编译过程：形参 a=3 → 函数声明 function a(){} 覆盖 a → var a 声明被忽略（已存在）→ 执行时 a=2 赋值覆盖。

  5.js — var 无块级作用域，会泄漏

  function varTest(){
    var x = 1;
    if(true){
      var x = 2;        // 同一个 x！
      console.log(x);   // 2
    }
    console.log(x);     // 2（被内层覆盖了）
  }
  var 只有函数作用域，if 块内的 var x 和外层的 x 是同一个变量。

  6.js — let 有块级作用域，互不干扰

  function varTest(){
    var x = 1;           // 在变量环境中
    if(true){
      let x = 2;         // 在词法环境的新块中
      console.log(x);    // 2
    }
    console.log(x);      // 1（外层没被影响）
  }
  查找顺序：先在词法环境（当前块）找 x → 找到 2；外层块在词法环境中找不到 → 去变量环境找 → 找到 1。

  7.js — 块级作用域内 var 和 let 的混合行为

  function foo(){
    var a = 1;      // 变量环境
    let b = 2;      // 词法环境
    {
      let b = 3;    // 词法环境新块：b=3
      var c = 4;    // 变量环境：c=4（var 无视块）
      let d = 5;    // 词法环境新块：d=5
      console.log(a, b);  // 1, 3
    }
    console.log(b, c, d); // 2, 4, ReferenceError: d is not defined
  }
  关键：var c 穿透块作用域进入变量环境；let d 被困在块内，外部无法访问。

  8.js — let 不允许重复声明（语法错误）

  let a = 1;
  function a(){}   // ❌ SyntaxError: Identifier 'a' has already been declared
  let 与同名的 function 声明在同一作用域内冲突 → 语法错误。而 var 和 function 同名则不会报错（函数优先）。

  ---
  三、知识体系总结

  读取代码 → 编译（创建执行上下文） → 执行
                  │
          ┌───────┴───────┐
          ▼               ▼
     变量环境          词法环境
    (var/function)    (let/const)
          │               │
          └───────┬───────┘
                  ▼
             调用栈（Call Stack）
          栈顶指针 → 当前执行上下文
                  │
                  ▼
          执行完毕 → 弹出 → 销毁

  核心要点：
  1. 编译先于执行 — JS 不是纯解释型语言，V8 有编译阶段
  2. 变量提升本质 — 编译阶段将声明放入环境，初始值为 undefined
  3. 函数提升优先 — 同名时 function > var，函数体整体提升
  4. 块级作用域靠词法环境 — let/const 通过词法环境的栈结构实现块隔离
  5. 查找链 — 词法环境（由内到外）→ 变量环境 → 作用域链
