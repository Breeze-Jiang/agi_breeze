# JS 执行机制
- 变量环境
 function,var 声明的都在变量环境中
- 词法环境
 let,const 声明的都在词法环境中
- 执行的代码
  从上到下，顺序执行
- 上面三者都在执行上下文对象中
- 执行栈/调用栈
 v8 引擎用来管理函数之间的调用关系的一种数据结构
 - 编译总在发生执行前一刻
 - 全局和函数体编译会在生成执行上下文对象，存入调用栈
 - 当一个函数执行完毕后，它的执行上下文对象会被弹出调用栈，销毁
 还没运行代码时，调用栈是空的

## 编译过程
- 创建执行上下文对象
- 找形参和变量声明，将形参和声明的变量名作为key，值为undefined
- 统一形参和实参的值（全局没有这个操作）
- 找函数声明，将函数名作为key，值为函数体

## 总结
执行上下文对象
编译阶段，先编译再执行
js 执行流程
读取代码 编译 执行
调用栈
负责函数之间的调用关系

## let const 
词法环境支持块级作用域 
仍然使用栈来管理不同作用域的变量
调用栈是执行上下文的容器
栈顶指针 指向当前正在执行的函数/全局
let const（但在编译阶段会分配到词法环境中） 不能重复声明 也不会变量提升 会进入暂时性死区中
