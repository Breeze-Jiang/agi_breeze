## 一页速览

> [!summary]
> - 前端项目通过 `npm run build` 产出静态文件，后端 Node.js 项目对外提供 `/api` JSON 接口。
> - 用户访问网站时，DNS 将域名解析为 IP，安全组和防火墙决定端口是否放行。

> - 云服务器部署通常还涉及 HTTPS、域名备案、Node.js 版本管理、MySQL 数据库和开发/生产环境隔离。

## 知识地图

```text
域名
  ↓ DNS 解析
云服务器公网 IP
  ↓ 安全组/防火墙放行 80、443 等端口
Nginx
  ├── 返回 React + TypeScript 构建后的静态文件
  └── /api 请求反向代理到 Node.js 端口
                         ↓
                       MySQL
```

## 核心知识

### 1. 前后端分离的产物

材料事实：前端 React + TypeScript 在开发阶段使用 `npm run dev`，发布阶段使用 `npm run build` 生成静态文件，例如 `dist`。后端 Node.js 对外提供 `/api` 接口并返回 JSON。

合理推断：生产环境不应把 `npm run dev` 当作前端服务，而应由 Nginx 返回构建后的静态文件；Node.js 只负责动态业务接口。

### 2. DNS 与访问入口

材料事实：浏览器输入域名后，DNS 将域名转换为 IP 地址。材料还列出了本机缓存、递归 DNS、根域名服务器、`.com` 顶级域名服务器和权威 DNS 服务器这一查询链路。

关键边界：DNS 负责“找到服务器”，不负责执行业务，也不等于 Nginx。找到 IP 后，请求还要经过安全组、防火墙和 Nginx。

### 3. 安全组与防火墙

材料事实：安全组位于云厂商网络层，控制哪些端口允许外网访问；防火墙位于服务器操作系统内部。材料将它们比作外层保安和内部门。

实践判断：公网通常需要开放 80（HTTP）和 443（HTTPS）；MySQL 的 3306 不应无条件开放给整个公网。材料提到开发/生产访问控制，但没有给出具体白名单规则。

### 4. Nginx 的三类职责

材料事实：Nginx 是高性能 Web 服务器，主要做三件事：接受请求、返回静态文件、把请求转发给后端。

```text
用户请求
  ↓
Nginx
  ├── 静态资源：直接返回构建产物
  └── 动态 API：反向代理给 Node.js
```

### 5. Node.js 与端口

材料事实：笔记示例中将前端请求 `/api/todos` 交给 Nginx，再由 Nginx 反向代理到服务器的 Node.js 端口；另处提到后端可能使用 3001 或 3006 端口。

未知信息：材料没有固定最终端口，也没有给出实际 `proxy_pass` 配置。端口应以 Node.js 实际监听端口和 Nginx 配置为准。

### 6. 宝塔与 Linux

材料事实：服务器使用 Linux；宝塔是可视化面板，常用网站目录为 `/www/wwwroot`，面板服务示例端口为 8888。

边界：宝塔是管理工具，不是操作系统；Nginx、Node.js、MySQL 仍然是实际运行的服务。面板端口也应进行安全限制。

### 7. 数据库环境

材料事实：笔记建议安装 MySQL，并建立 `dev` 与 `production` 两个库，使开发和线上数据互不影响。

实践判断：环境隔离能降低测试数据污染线上数据的风险。材料没有给出用户、权限、备份和迁移方案。

### 8. Node.js 版本管理

材料事实：笔记建议使用 nvm 管理 Node.js 版本，因为不同项目可能有不同版本需求。

## 注释重点解读

材料中的关键解释是“`/api/todos` 在开发阶段由 Vite 的 mocks 拦截，在生产阶段由 Nginx 反向代理到后端端口”。这说明开发环境与生产环境可以使用相同的请求路径，但请求实际处理者不同。材料未提供 Vite 或 Nginx 配置，因此具体匹配规则仍需结合项目文件确认。

## 面试高频知识

1. **DNS 和 Nginx 的区别？** [材料推导] DNS 将域名找到 IP；Nginx 接收到请求后返回资源或代理到后端。
2. **为什么前端生产环境要 build？** [材料中出现/材料推导] 开发服务用于开发调试，build 生成可由 Web 服务器直接提供的静态资源。
3. **安全组和防火墙有什么区别？** [材料中出现] 前者在云厂商网络层，后者在服务器操作系统内，实际访问通常需要两层都允许。
4. **为什么 API 使用 `/api` 前缀？** [材料中出现/材料推导] 便于 Nginx 根据路径把动态请求分流给后端。
5. **3306 是否应该开放公网？** [材料推导] 不应默认对所有公网开放，应限制来源或仅允许内网访问；材料未给出具体规则。
6. **宝塔是什么？** [材料中出现] Linux 服务器上的可视化管理面板，不是替代 Linux 或业务服务的操作系统。
7. **开发库和生产库为什么分开？** [材料中出现] 避免开发和线上互相影响。
8. **nvm 解决什么问题？** [材料中出现] 不同 Node.js 项目需要不同版本时，可以切换运行环境。

## 复习卡片

- [!tip] **请求链路**：域名 → DNS → 公网 IP → 安全组/防火墙 → Nginx → 静态文件或 Node.js → MySQL。
- [!warning] **常见误区**：DNS 不是业务服务器；宝塔不是操作系统；`npm run dev` 不是生产前端部署产物。
- **端口记忆**：80 是 HTTP，443 是 HTTPS，3306 是 MySQL；真实项目还要以配置为准。
- **分流记忆**：`/` 常用于前端静态资源，`/api` 常用于后端动态接口。
- **环境记忆**：dev 和 production 数据库分开，配置和密钥也应按环境隔离。
